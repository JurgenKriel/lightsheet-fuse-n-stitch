## Deviation: plan's "cells 0..8 byte-identical to HEAD" check was impossible

Plan 05 specified that cells 0..8 must be byte-identical to HEAD after the append. That check could not be run literally because:

- **HEAD's notebook has 7 cells**, not the 9 the plan assumed.
- The pre-edit worktree had 9 cells = HEAD's 7 + 2 pre-existing uncommitted WIP cells the user added before this session (similar to the WIP on `07_direct_fuse.py`).
- The plan was drafted against the worktree state, not HEAD.

The substantive invariant — "don't destroy existing user cells" — was satisfied: `nbformat.write` is content-aware and preserved every existing cell's source. The diff is large in line count (517 insertions / 58 deletions) because nbformat normalized the JSON serialization of every cell (whitespace, line-splitting in the `source` arrays), but no semantic content changed in the existing cells. Their `"".join(source)` strings are identical to the pre-append state.

This means plans 04, future phase verifiers should use **content equivalence** (`"".join(source)` per cell) as the cell-stability check, not byte-level JSON diff.

## How to use

1. Run `08_stitch_stage1_register.sh` (plan 04) to produce `stitch_diagnostics.json` + `stitch_positions.json` in `OUT_DIR`.
2. Open `08_fusion_dev.ipynb`, change PARAMETERS cell's `OUT_ZARR` to point at `fused_direct.zarr` (instead of the default substack path) if you want the illumination panel to crop from the full-stack fused output rather than a substack.
3. Run the new Phase 2.5 cell. Look for: solver `converged: True`, mean NCC ≥ 0.85, max residual ≤ 5 px, all bars in Panel 3 below the red 1.15 line.
4. If targets miss, tune Stage 2 blending widths (plan 03) or re-run Stage 1 with a different z-slab (Stage 1 `--z-mid` / `--z-slab-half`).

## Failure mode if Stage 1 hasn't run

The cell raises `FileNotFoundError: stitch_diagnostics.json` — by design, loud and clear. That's the desired UX (user knows they need to run Stage 1 first).
