## What was built

Two SLURM submission scripts in `scripts/lightsheet_pipeline/`:

- **`08_stitch_stage1_register.sh`** — single GPU job (gpuq, A30, 16 cpus, 80G mem, 1h). Activates `mvstitch_env`, runs `08_stitch.py --stage register`, asserts the JSON outputs exist, then recreates `fused_direct.zarr` at the registered canvas size (H, W computed from `stitch_positions.json`) with a defensive bounds check so a bizarre registration result can't accidentally overwrite the Phase 2 zarr with a wrong shape.
- **`08_stitch_stage2_blend.sh`** — SLURM array 1-8 (gpuq, A30, 6 cpus, 150G mem, 2h). Each task fuses a disjoint Z-slab into the shared `fused_direct.zarr` via `08_stitch.py --stage blend`. Z-partition is identical to Phase 2 plan 02-02 (Z_STARTS=(0 256 448 640 832 1024 1216 1408), Z_ENDS=(256 448 640 832 1024 1216 1408 1557)) so no two tasks touch the same zarr chunk (chunk size 64, all boundaries multiples of 64).

Both scripts use the `command -v module` guard pattern (matches recent fix commits aee38db / 4223e26), the correct conda profile path (`/stornext/System/data/apps/anaconda3/anaconda3-latest/etc/profile.d/conda.sh`), and activate `mvstitch_env` (NOT `lightsheet_env`).
